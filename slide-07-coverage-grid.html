Test Behavior, Boundaries, And Reuse

These eval categories play the same role as test-case categories in traditional development: proving behavior, boundaries, and change safety.

P

Positive

  • Triggers correctly and produces expected results
N

Negative

  • Refuses or redirects out-of-scope requests
G

Guardrail

  • Stop gates and workflows are not bypassed
  • Out-of-scope work is refused
  • Required questions are asked in order
R

Regression

  • Previously solved cases keep passing
E

Extension

  • Can add capabilities without breaking core logic
  • Uses references/ and templates/ correctly
M

Minimal change

  • Avoids unnecessary edits and extra work
  • Keeps changes strictly within scope
